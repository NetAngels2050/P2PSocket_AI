# 客户端 Web 易用性/美观性评估报告 —— 2026-10-20

- **来源**：用户指令"现在对客户端的 web 易用性、美观性进行评估"。批复口径：**仅出评估报告，不改代码**；改进建议按用户倾向排序——**设计令牌+共享样式层、图标体系**优先，深色模式/窄屏响应式暂缓；ui-shared 视觉层改动允许两端（客户端 7100 / 服务端管理页 7500）一并受益。
- **方法**：全量代码审读（信息架构/交互流 + 样式体系两路），关键论断逐条抽查实证（登出无确认、maxlength=8、离线点三色、全仓零 `@media`、echarts 死依赖五项均已核实到行）。未做实机截图走查；实施批次时可用 §0.3 mock 入口补走查。

## 0. 范围与方法

### 0.1 评估对象

`web/client-app` 全部 10 页（Dashboard / Wizard / Login / Devices / Groups / Segments / Mappings / Logs / Settings / Upgrade，共 10 条 hash 路由）+ `web/ui-shared`（AdminLayout 布局、StatusTag / CodeText / DeviceCard 共享组件）。服务端管理页（server-app）不在本次范围，但与客户端共用 AdminLayout 与视觉语言，结论大体互通。

### 0.2 技术底座

Vue 3.5（`<script setup>` + TS）+ Pinia + vue-router（hash）+ Vite 8；**UI 组件库 = Element Plus 2.14.4 全量引入，主题零定制**；状态刷新 = 单 WS `/ws/status` 推送（数值 1s 直写、状态类 100ms debounce 触发 REST refetch）+ 10s 轮询兜底。

### 0.3 实机走查入口（备忘）

`web/` 目录下 `VITE_USE_MSW=1 pnpm --filter @p2p/client-app dev` → <http://localhost:5173>。MSW 为带内存态的全端点镜像（账号 `demo / secret123`；3 台设备、3 条映射[direct/failed/relay]、2 个分组含所有者+待审批），覆盖绝大多数交互路径。**注意**：MSW 只拦 HTTP 未拦 `/ws/status`，mock 模式下顶栏常驻"本地服务不可达"红字属环境假象非 bug。

## 1. 总体结论

- **易用性：底盘扎实，细节有漏。** 交互基建（loading 防重、危险操作确认、空态引导、错误码中文化）高于一般内部工具水准；缺陷集中在**一致性**（术语/错误呈现/离线色）与**防护缺口**（登出无确认）。
- **美观性：偏弱——"Element Plus 出厂态素颜"。** 全部视觉决策委托组件库默认主题：零设计令牌、零品牌化、零图标、零响应式断点、零自写动效；另有一批复制粘贴导致的样式漂移。克制、统一是优点，但美观上限被锁死在出厂态。

## 2. 易用性发现

### 2.1 做得好的（保持，勿在后续改动中丢失）

1. **提交/操作按钮 `:loading` 防重全站覆盖**：向导测试/注册、分组入组/新建/编辑/邀请码、映射保存、网段添加、设置保存、设备改名、STUN/PING/服务端探测/REKEY 诊断逐一齐备。
2. **危险操作二次确认带具体后果说明**（6 项）：重置远程码"旧远程码立即失效：引用旧码的映射与打洞请求将被拒绝（4003）"、解散分组"组内全部成员的跨分组可见性即时回收，不可恢复"、移除网段"段内存量映射将失效"等——确认文案质量高于一般水准，不是裸"确定吗"。
3. **空态文案全带引导**："暂无映射，点击右上角新建""暂未加入任何分组（凭码入组或新建）""暂无开放网段（除 self 外全部目标地址将被拒绝）"，非裸"暂无数据"；无数据单元格统一"—"占位。
4. **错误码全量中文映射**：`useApi.ts` ERROR_TEXT 20 项（5001→打洞失败、4005→目标设备离线等），未覆盖兜底"错误 {code}"。
5. **重要信息强呈现**：重置远程码成功用模态"我已记下"（防抄完即丢）；CodeText 一键复制 + 1.5s"已复制"反馈。
6. **向导第①步强制先测连通性**（`canNext` 钳制 + 强点提示"请先完成连通性测试"），防用户填错服务端地址一路走到黑；第③步先呈现远程码/虚拟 IP 再放行离开。
7. **状态自动刷新**：WS 推送 + 10s 轮询兜底 + visibilitychange resync，列表页另有手动刷新按钮。
8. **改密成功主动登出引导重登**；哑节点横幅 + 写操作全置灰的全站联动；网段冲突常驻红条带明细与处置建议。
9. **邀请码两入口共享校验规则 + 提交归一**（8004aa2 后口径统一，杜绝再漂移的共享规则模式值得推广）。

## 3. 美观性发现

### 3.1 现状与亮点

**现状**：全部视觉决策委托 Element Plus 默认主题——主色 EP 工厂蓝 `#409eff`、纯白背景；全 web 源码**零自定义色值**（hex/rgb 搜索 0 命中，颜色全部 `var(--el-*)`）、**零全局样式文件**（除 EP dist 外无任何 .css）、无 logo/favicon、无图标库、自写 transition/animation 零命中。

**亮点（保持）**：语义色纪律严明（危险必 `danger plain`、次要必 `primary plain`、行内必 `size="small"`，抽查五页零违例）；圆角 100% 走 `--el-border-radius-base`（无一处写死 px）；StatusTag 六态成套（语义色 + 同色浅边框）；骨架屏/空态/禁用态覆盖规范；client/server 两端观感完全一致（同一 AdminLayout）。
