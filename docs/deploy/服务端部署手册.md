# 服务端部署手册

> 适用版本：1.0.0　依据：NFR-31/34、设计 08 §3.3/§5.1/§7、D11　随版交付（M4-07）
> 两种形态：**A. 裸机 Linux 单文件 + systemd**（生产现网形态）／**B. Docker + compose**（NFR-34）。
> 实施实录（含逐条命令输出）见 [docs/部署文档/公网服务端部署.md](../部署文档/公网服务端部署.md)（保留作 M1-37 验收记录，最新口径以本手册为准）。

## 0. 产物与构建

```bash
# 构建机（仓库根目录；自动前置构建 server-app 前端）
sh build/package.sh server
# 产物 out/server/：p2p-server（linux-x64 自包含单文件 ~102MB）+ libe_sqlite3.so
#   + appsettings.json + staticwebassets.endpoints.json + wwwroot/
```

- 单文件自包含：目标机**免装 .NET**（NFR-31）；
- 版本号/构建信息：`src/Directory.Build.props` 统一注入（1.0.0+git 短哈希），服务端仪表盘左上角可查。

## 1. 端口与安全组清单（云控制台放行）

| 端口 | 协议 | 用途 | 是否放行公网 |
|---|---|---|---|
| 7000 | TCP | 控制面 PCP（注册/登录/信令/映射） | **必须** |
| 3478 | UDP + TCP | STUN 打洞探测 / STUN-TCP 桥接 | **必须（两种协议都放）** |
| 7010-7020 | TCP + UDP | 中继数据面（中继回退客户端的承载） | **必须（两种协议都放）** |
| 7500 | TCP | 服务端 Web 管理后台 | **不放行**（仅本机回环，见 §4 D11） |

- UDP 3478 连通性验证注意：`stun_auth` 默认开启，未带设备鉴权的裸 STUN 探测会被**静默丢弃**——"无响应≠不通"。正确姿势=服务器 `tcpdump -ni any udp port 3478` 抓包看 In 方向到达。
- **public_addr（NAT 通告，必配）**：云 VPS 网卡通常只见内网地址，中继 RelayGrant 会把内网端点通告给客户端导致不可达（M2-36 实录）。在管理后台「系统配置」把 `public_addr` 设为**宿主公网 IP**（库键 server_config，非 appsettings）。

## 2. 形态 A：裸机 Linux + systemd

### 2.1 安装（首次）

```bash
# ① 上传（构建机执行；tar 管道直解压，pdb 不上传）
tar -C out/server -czf - --exclude='*.pdb' p2p-server libe_sqlite3.so appsettings.json \
    staticwebassets.endpoints.json wwwroot \
  | ssh root@<服务器IP> "mkdir -p /opt/p2p/server && tar -C /opt/p2p/server -xzf -"

# ② 服务器侧：专用非特权账户 + 数据目录属主/权限（M5-11 最小权限，SEC-81，07 §14.1）
ssh root@<服务器IP> '
useradd -r -s /usr/sbin/nologin p2p
mkdir -p /opt/p2p/server/data /opt/p2p/server/logs
chown -R p2p:p2p /opt/p2p/server/data /opt/p2p/server/logs
chmod 750 /opt/p2p/server/data /opt/p2p/server/logs
chmod +x /opt/p2p/server/p2p-server'

# ③ systemd 单元（仓库文件 deploy/server/p2p-server.service——非特权+沙箱，M5-11）+ 启动
scp deploy/server/p2p-server.service root@<服务器IP>:/etc/systemd/system/p2p-server.service
ssh root@<服务器IP> 'systemctl daemon-reload && systemctl enable --now p2p-server'
```

要点：**WorkingDirectory 必须指向部署目录**（数据库/日志均为相对路径）；`Restart=always`+5s 崩溃自愈（NFR-53）。**M5-11 起 unit 含最小权限与沙箱指令**——`User=p2p` 非特权运行、`ProtectSystem=strict` 全文件系统只读（仅 data/logs 白名单可写，`ReadWritePaths`）、`NoNewPrivileges`/`ProtectHome`/`PrivateTmp`、`AmbientCapabilities=CAP_NET_BIND_SERVICE` 授权 3478 低口绑定（唯一特权点，`CapabilityBoundingSet` 同步收敛）；部署目录其余文件保持 root 属主只读（p2p 用户仅需 r-x——连自身二进制都不可篡改）。存量 root 部署迁移见 §2.8。

### 2.2 首启初始化与验证

- 首启自动：建库（EF 迁移+幂等种子 server_config）→ 内置管理员 **admin/admin** → 默认分组。**首登后立即改密**（管理后台强制）。
- **单文件首启须等 ~12s**（自解包+迁移），`systemctl status` 短暂 `activating` 属正常，勿在脚本里用 `is-active` 立即判定。
- 验证清单：

```bash
systemctl status p2p-server --no-pager | head -5      # active (running)
ss -lntup | grep p2p-server                            # 0.0.0.0:7000/tcp、3478/udp+tcp、7010-7020、127.0.0.1:7500
journalctl -u p2p-server -n 10 --no-pager              # 「数据库就绪」「控制面监听…」「STUN-R 监听…」「服务端启动完成」
ls /opt/p2p/server/data /opt/p2p/server/logs           # p2p.db(+wal/shm)、app-<日期>.log
```

### 2.3 管理后台接入（D11：不对公网监听）

`appsettings.json` 生产默认 `listen.webBind=127.0.0.1`——管理面**仅服务器本机回环**可达。跨机接入两种方式：

1. **SSH 隧道**（运维兜底）：`ssh -L 7500:127.0.0.1:7500 root@<服务器IP>` → 本机浏览器 `http://127.0.0.1:7500`；
2. **经客户端映射接入**（正式路径，现网在用）：服务器本机跑一个 p2p-client（见 Linux 客户端手册）+ 家里电脑建映射 `本地端口 → 服务器设备远程码:self:7500`，经隧道访问。

**不要**把 webBind 改 0.0.0.0 并放行 7500——管理面直接暴露公网。

### 2.4 配置参考

**appsettings.json（进程级：端口/路径）**——设计 08 §5.1：

| 键 | 默认 | 说明 |
|---|---|---|
| `listen.control` | 7000 | 控制面 TCP |
| `listen.stunUdp` / `listen.stunTcp` | 3478 / 3478 | STUN 双协议（客户端按控制地址派生，勿改） |
| `listen.relayPorts` | [7010, 7020] | 中继数据面端口段（TCP+UDP） |
| `listen.web` / `listen.webBind` | 7500 / **127.0.0.1** | 管理后台端口/绑定（D11 保持回环） |
| `database.path` | data/p2p.db | 相对 WorkingDirectory |
| `logging.retentionDays` | 14 | 滚动日志保留 |

**server_config 库键（业务级，管理后台「系统配置」页改，含重启生效标注）**：`public_addr`（见 §1）、`relay_enabled`/`relay_rate_limit`、`stun_auth`/`stun_alt_addr`/`stun_rate_*`、`update_*`（升级引导）、`default_join_policy`、`registration_open`、`max_devices`、`virtual_subnet`、`log_level` 等 19 键。端口/路径在文件、业务开关在库（08 §5.1 分工）。

### 2.5 升级与回滚（FR-C-904，08 §7）

```bash
# ① 构建机发布并上传（覆盖不含 data/logs——数据库与日志天然保留）
sh build/package.sh server
tar -C out/server -czf - --exclude='*.pdb' p2p-server libe_sqlite3.so appsettings.json \
    staticwebassets.endpoints.json wwwroot | ssh root@<IP> "tar -C /opt/p2p/server -xzf -"
# ② 服务器：先备份再切换（回滚件）
ssh root@<IP> 'cp /opt/p2p/server/p2p-server /opt/p2p/server/p2p-server.bak-$(date +%Y%m%d)
chmod +x /opt/p2p/server/p2p-server && systemctl restart p2p-server'
# ③ 验证（首启 ~12s 等待后再判）
ssh root@<IP> 'sleep 15 && systemctl is-active p2p-server && journalctl -u p2p-server -n 5 --no-pager'
```

- EF 迁移自动前滚（NFR-36；迁移在容器构建前先行执行——P0 启动序修复后任何版本读写点均安全）。
- **回滚**：`cp p2p-server.bak-<日期> p2p-server && systemctl restart p2p-server`。注意 schema 只进不退，跨版本回滚不建议（降版本前先停用新版本用过的功能面）。
- appsettings.json 覆盖后线上手工改动会丢——改过线上配置则上传时排除该文件。
- **unit 不随升级覆盖**（上述命令只动二进制）；unit 本身变更时（如 M5-11 沙箱化）按 §2.8 迁移节替换。

### 2.6 日常运维

```bash
systemctl status|restart p2p-server
journalctl -u p2p-server -f                                   # systemd 侧
tail -f /opt/p2p/server/logs/app-$(date +%Y%m%d).log          # 应用日志
cd /opt/p2p/server && ./p2p-server --reset-admin              # admin 密码重置（07 §9 R6）
```

数据备份=停服务后打包 `/opt/p2p/server/data/`（SQLite WAL 安全点）；启用静态数据加密（§2.7）后**备份必须连同 masterKey**。

### 2.7 静态数据加密（可选，SEC-83，M5-13）

`devices.device_secret` 支持落库加密（AES-256-GCM，密文 61B；EF 值转换器透明加解密——读写路径零改动）。**默认不启用**：不配置=明文存储+启动 ERROR 日志+管理后台「安全」页顶部警示横幅（P2 纵深防御层，不阻断启动——07 §14.3）。

```bash
# ① 生成 64 hex（32B）主密钥
openssl rand -hex 32
# ② 写入 /opt/p2p/server/appsettings.json（或环境变量 P2P_MASTER_KEY 优先——密钥不落库）：
#    "security": { "masterKey": "<64hex>", "masterKeyPrev": "" }
# ③ 重启即自动迁移存量明文（日志「静态数据加密迁移完成：加密/重加密 N 行」），此后全量 61B 密文
systemctl restart p2p-server
```

- **备份必须连同 masterKey**——丢钥=旧库凭据不可解，全部设备须管理后台解绑后重注册（07 §14.3 运维警示）；钥在 appsettings 则备份该文件即含钥，钥在环境变量/systemd 单元则一并备份；
- **轮换**：新钥填 `masterKey`、旧钥移入 `masterKeyPrev` 重启（启动把旧密文重加密为新钥），日志确认后清空 `masterKeyPrev`（双钥并存窗口=一次启停）；
- **升级部署**（§2.5）注意：上传覆盖 appsettings.json 会丢线上 masterKey——已配置的环境上传时排除该文件（该既有警示随钥升级为强警示）；
- 库文件权限：启动自动核对 `data/p2p.db`（含 -wal/-shm）为 0600；目录级 0750 与非特权运行见 §2.8（M5-11）。

### 2.8 存量 root 部署迁移至最小权限（M5-11，SEC-81，A-18 前半）

2026-10-23 前部署以 root 运行（旧 unit 无 `User=`/沙箱指令）。迁移四步，停机约 1 分钟（客户端自动退避重连，无需用户干预）：

```bash
# ① 备份（回滚件：数据目录 + 旧 unit）
ssh root@<IP> 'systemctl stop p2p-server \
  && cp -a /opt/p2p/server/data /root/p2p-data-bak-$(date +%m%d) \
  && cp /etc/systemd/system/p2p-server.service /root/p2p-server.service.bak-$(date +%m%d)'
# ② 专用账户 + 数据目录属主（部署目录其余文件保持 root 属主只读——p2p 用户仅需 r-x）
ssh root@<IP> 'useradd -r -s /usr/sbin/nologin p2p \
  && chown -R p2p:p2p /opt/p2p/server/data /opt/p2p/server/logs \
  && chmod 750 /opt/p2p/server/data /opt/p2p/server/logs'
# ③ 替换 unit（仓库 deploy/server/p2p-server.service）+ 起服
scp deploy/server/p2p-server.service root@<IP>:/etc/systemd/system/p2p-server.service
ssh root@<IP> 'systemctl daemon-reload && systemctl start p2p-server'
# ④ 核对（身份/监听/沙箱拒绝）
ssh root@<IP> 'ps -o user= -C p2p-server | sort -u      # 期望 p2p
  ss -lntup | grep p2p-server                           # 7000、3478/udp+tcp、7010-7020、127.0.0.1:7500
  journalctl -u p2p-server --since "-2 min" --no-pager | grep -iE "EACCES|denied|只读|启动完成"'
```

- **功能验证（A-18 前半——非 root 全功能履职）**：既有客户端断线自动重连（凭据重放）＋新设备注册＋STUN 判型/打洞＋中继回退＋Web 后台（SSH 隧道 `-L 7500`）各过一遍；
- **沙箱白名单核对**：journal 无 `EACCES`/`Read-only file system` 报错＋当日日志文件与库 WAL 正常写入（`ProtectSystem=strict` 下任何越界写会直接 ERROR/启动失败，不会静默——服务活着且在写=白名单正确）；单文件自解包的 native 库落 `PrivateTmp` 私有 /tmp，同属启动成功自证；
- **masterKey 注意**：已启用 §2.7 加密且密钥置于 unit `Environment=`/`EnvironmentFile` 时，新 unit 须同款保留——推荐放 drop-in（`/etc/systemd/system/p2p-server.service.d/` 目录**不受 unit 文件替换影响**）；
- **回退**（一次启停回 root 形态，库内容无差别）：

```bash
ssh root@<IP> 'cp /root/p2p-server.service.bak-* /etc/systemd/system/p2p-server.service \
  && systemctl daemon-reload \
  && chown -R root:root /opt/p2p/server/data /opt/p2p/server/logs \
  && systemctl start p2p-server'
```

## 3. 形态 B：Docker + compose（NFR-34）

详见 [deploy/server/docker/README.md](../../deploy/server/docker/README.md)（构建/启动/升级换镜像/数据迁移/webBind 容器化口径）。要点摘录：

```bash
sh build/package.sh server
docker build -f deploy/server/docker/Dockerfile -t p2p-server:1.0.0 out/server
cd deploy/server/docker && docker compose up -d        # ./data 卷=库+日志；升级=换 tag 再 up -d
```

- 镜像内 `/app/logs` 符号链接进 `/data` 卷（日志落卷）；环境变量覆盖 `listen__webBind=0.0.0.0`（仅容器命名空间内生效）；
- **compose 端口映射 `127.0.0.1:7500:7500` 回环前缀是 D11 双保险，禁止改裸 `7500:7500`**；
- **M5-11 非 root 化**：镜像 `USER p2p`（uid 1000）；`./data` 卷属主须对齐 `chown -R 1000:1000 ./data`（root 属主旧卷直接换镜像=库打不开起不来）；环境裁剪 cap 时 `--cap-add=NET_BIND_SERVICE`（3478 低口）——详见 [docker/README.md](../../deploy/server/docker/README.md)；
- `public_addr` 仍是库键，容器环境变量不覆盖业务键（管理后台改）。

## 4. 环境要求与容量参考

- Linux x64（Debian 12 验证；glibc 2.31+）；免装 .NET/SQLite；
- 规格：2C/2GB VPS 实测承载 500 设备（=max_devices 默认上限）稳态 CPU<1%、WS ~236MB（基准报告 §3.7），中继吞吐受带宽与两端 CPU 约束；
- 时间同步：协议含时钟偏差校验（5005 TIME_SKEW），服务器须运行 NTP（云镜像默认已配）。
