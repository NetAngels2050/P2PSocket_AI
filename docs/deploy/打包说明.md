# 打包说明

> 适用版本：1.0.0　依据：设计 08 §1（版本注入）/§2⑤/§3、NFR-31~33　维护期交付（2026-10-21；2026-10-23 随 M5-14/SEC-84 增 .sha256 清单与 SHA256SUMS 汇总——07 §14.4）
> **分发口径：Windows = Setup exe（Inno Setup 安装包）／Linux = tar.gz（服务端 + 客户端各一枚）**；deb/rpm/Docker 为可选扩展形态，见各部署手册。
> **命名口径（2026-10-21，PRD v0.12/设计 v1.65）**：分发件统一 `P2PSocket-*` 前缀；安装器显示名「P2PSocket 客户端」。**服务名 `P2PClient` 与数据目录 `%ProgramData%\P2PClient` 刻意不改**——已装机覆盖升级与数据保留依赖二者。
> 打包入口唯一：`sh build/package.sh`（M4-01 落地）。构建机为 Windows（Git Bash）；产物对目标平台自包含，免装 .NET。

## 0. 打包链路（一段话）

前端 `pnpm build`（产物直写宿主项目 wwwroot）→ `dotnet publish -c Release -r <RID> -p:PublishSingleFile=true -p:SelfContained=true`（单文件自包含）→ `out/` 产物目录（脚本自动校验：可执行体 + wwwroot/index.html 在位）→ Linux 目标追加 `tar.gz` 归档／Windows 安装包目标经 ISCC 编译成单 exe。

```text
sh build/package.sh <目标>
  ├─ pnpm -C web --filter <前端包> build      # client-app 或 server-app
  ├─ dotnet publish src/<P2P.Client|P2P.Server> -r <win-x64|linux-x64> → out/<目录>/
  ├─ [Linux] tar -czf out/p2p-<目标>-v<版本>.tar.gz -C out/<目录> .
  └─ [win-setup] ISCC 编译 deploy/client/win/P2PSocket-Client.iss → out/P2PSocket-Client-Setup-<版本>-x64.exe
```

## 1. 版本号从哪来（两条）与打包纪律

| 来源 | 去向 |
|---|---|
| `src/Directory.Build.props` 的 `<Version>`（当前 **1.0.0**，手动递进——单一事实源） | 归档文件名 `v1.0.0`、Setup exe 文件名、运行时 `/api/system/state` 的 `version` 字段 |
| `git rev-parse --short HEAD` + 构建 UTC 时间 → `ThisAssembly.Metadata`（GitCommit/BuildDate；`SOURCE_DATE_EPOCH` 存在时作可重现构建口径） | 运行时 `/api/system/state` 的 `commit` 字段、日志启动行 |

- **纪律：打包前先 `git commit`**——注入的是 HEAD 哈希，工作区未提交的改动不会体现在版本号里，线上排障会对不上 commit（2026-10-18 教训：升级须「先提交、再自 HEAD 重打包」）。
- git 不可用（源码包构建）容错为 `unknown`，不阻断构建。

## 2. 环境依赖

| 依赖 | 用途 | 说明 |
|---|---|---|
| dotnet SDK 10 | publish | — |
| node ≥20 + pnpm | 前端构建 | `corepack enable pnpm` |
| Git | 版本哈希注入 | — |
| Inno Setup 6（仅 win-setup） | 编译安装包 | `winget install JRSoftware.InnoSetup`；脚本探测 Program Files (x86)/Program Files/用户级三处 ISCC.exe，未装则**跳过安装包并如实标注**（不报错） |
| Wintun.dll（仅 client-win） | Windows TUN 驱动库 | 官方 wintun.net 0.14.1 amd64，**不入库**；置于 `out/wintun/Wintun.dll` 后脚本自动拷入产物，缺失则警告并要求分发前手工放置（08 §3.1） |

## 3. 命令与产物对照

仓库根执行：

| 目标 | 命令 | 产物（out/） | 形态 |
|---|---|---|---|
| **win-setup** | `sh build/package.sh win-setup` | `P2PSocket-Client-Setup-1.0.0-x64.exe`（~36MB） | **Windows 分发件（exe）**；内部先跑 client-win 再 ISCC |
| **server** | `sh build/package.sh server` | `server/`（目录）+ `P2PSocket-server-v1.0.0.tar.gz` | **Linux 分发件（tar.gz）**，linux-x64 |
| **client-linux** | `sh build/package.sh client-linux` | `client-linux/`（目录）+ `P2PSocket-client-linux-v1.0.0.tar.gz` | **Linux 分发件（tar.gz）**，linux-x64 |
| client-win | `sh build/package.sh client-win` | `client-win/`（目录，**无归档**） | portable 形态：已装服务的覆盖升级 / 手工部署用（Windows 手册形态 B） |
| all（缺省） | `sh build/package.sh` | client-win + client-linux + server 三目标 | 不含 win-setup |

> 每个分发件（Setup exe / 两枚 tar.gz）随打包自动产出同名 `.sha256` 清单（单行 `<小写hex64>␣*<产物文件名>`=GNU sha256sum binary 标记——Git Bash 缺省输出，`sha256sum -c` 各平台按二进制读；M5-14/SEC-84），另汇总 `out/SHA256SUMS`（多行同格式，按在位分发件幂等重建）——目标机 `sha256sum -c <清单>` 直接核验（Windows 手册指引 `Get-FileHash` 比对）。分发件哈希可录入服务端管理页「升级-产物SHA-256」（server_config `update_artifact_sha256`，JSON 键 windows-setup/linux-tar/server-tar），升级页按平台展示（07 §14.4）。
> 单条命令只收一个目标（脚本 case 精确匹配）；多目标分别执行，或用缺省 `all`（= client-win+client-linux+server 三连，不含 win-setup）。范例文件名以当前 Version=1.0.0 为准，随 `Directory.Build.props` 递进而变。

### 3.1 完整命令范例·Windows（Setup exe 分发件）

```bash
# 前提：Git Bash + dotnet SDK 10 + node≥20/pnpm；Inno Setup 6（winget install JRSoftware.InnoSetup）；
#       Wintun.dll 已置于 out/wintun/Wintun.dll（缺失仅警告，产物须分发前手工放置）
cd /d/AICode/AI_P2P_Project                      # 仓库根
git status --short                                # ① 确认工作区干净——版本注入取 HEAD 哈希，未提交改动不进版本号
sh build/package.sh win-setup                     # ② 前端构建 → publish win-x64 单文件自包含 → ISCC 编译安装包
sha256sum -c out/P2PSocket-Client-Setup-1.0.0-x64.exe.sha256  # ③ 清单核验（M5-14 脚本自动产出）
# 产物：out/P2PSocket-Client-Setup-1.0.0-x64.exe（~36MB）——目标机双击安装（Windows 手册形态 A）
```

### 3.2 完整命令范例·Linux（tar.gz 分发件，服务端 + 客户端两枚）

```bash
# 前提：Git Bash（构建机为 Windows，产物对 Linux 自包含）+ dotnet SDK 10 + node≥20/pnpm
cd /d/AICode/AI_P2P_Project                      # 仓库根
git status --short                                # ① 同上：先提交、再自 HEAD 重打包
sh build/package.sh server                        # ② 服务端：server-app 构建 → publish linux-x64 → tar.gz
sh build/package.sh client-linux                  # ③ 客户端：client-app 构建 → publish linux-x64 → tar.gz
sha256sum -c out/P2PSocket-server-v1.0.0.tar.gz.sha256 \
          out/P2PSocket-client-linux-v1.0.0.tar.gz.sha256   # ④ 清单核验（M5-14 脚本自动产出）
# 产物：out/P2PSocket-server-v1.0.0.tar.gz（公网服务器）+ out/P2PSocket-client-linux-v1.0.0.tar.gz（设备侧）
# 目标机解包（顶层 ./ 散开，-C 直落目标目录；解包后 chmod +x，见 §5 坑 2）：
#   tar -xzf P2PSocket-server-v1.0.0.tar.gz -C /opt/p2p/server
```

## 4. 分发口径（Windows=exe，Linux=tar.gz）

- **Windows**：分发 `P2PSocket-Client-Setup-1.0.0-x64.exe`，目标机双击安装（[Windows 客户端部署手册](Windows客户端部署手册.md) 形态 A，装到 `C:\Program Files\P2PSocketClient` 并注册 `P2PClient` 服务）。已装服务的升级不必重跑安装包——直接用 `client-win/` 目录覆盖 exe+wwwroot（手册 §7 / 本机 ps1 升级流）。
- **Linux 服务端**：分发 `P2PSocket-server-v1.0.0.tar.gz` → [服务端部署手册](服务端部署手册.md)。
- **Linux 客户端**：分发 `P2PSocket-client-linux-v1.0.0.tar.gz` → [Linux 客户端部署手册](Linux客户端部署手册.md) 形态 C（deb/rpm 属可选扩展形态）。

## 5. 产物内容与解包注意

顶层内容（tar 归档为 `./` 散开，`tar -xzf xxx.tar.gz -C <目标目录>` 直落）：

| 件 | server tar | client-linux tar | client-win 目录 |
|---|---|---|---|
| 可执行体 | p2p-server | p2p-client | p2p-client.exe |
| wwwroot/（Web 静态资源） | ✓ | ✓ | ✓ |
| pdb（3 枚）+ staticwebassets.endpoints.json | ✓ | ✓ | ✓（另 web.config） |
| libe_sqlite3.so | ✓ | — | — |
| **appsettings.json（默认值）** | **✓（见下方坑）** | — | —（客户端配置在 ProgramData//etc，不随包） |
| Wintun.dll | — | — | ✓（out/wintun/ 在位时） |

**踩坑四条（历次实弹）：**

1. **server tar 含默认 appsettings.json**——线上解包会覆盖运行配置（webBind、心跳超时等）。远端升级必须「备份 appsettings.json → 解压 → 回放」三步（2026-10-21 实弹）。
2. **Windows 构建的 tar 丢执行位**——Linux 解包后须 `install -m 755 p2p-server <目标>` 或 `chmod +x`，否则 systemd 起 203/EXEC（2026-09-30 实弹）。
3. **exe 与 wwwroot 必须同目录**——SPA 静态托管按 AppContext.BaseDirectory 解析。
4. **版本验证走 `/api/system/state` 的 version/commit 字段**——`p2p-client --version` 不是有效参数，会真启动第二实例（端口冲突崩退，不影响已装服务但别用）；单文件首启有 ~12s 自解压期，期间 `systemctl is-active` 显示 activating 属正常，等再查。
