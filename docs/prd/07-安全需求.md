# 07 · 安全需求

> 所属文档集：[README](README.md)　编号前缀：SEC。协议实现不锁定（决策 D5），本文只约定**能力要求**。

## 1. 威胁模型（简表）

| # | 威胁 | 对策落点 |
|---|---|---|
| T1 | 中间人窃听/篡改 P2P 或中继链路 | SEC-1x 端到端加密 |
| T2 | 伪造服务端下发恶意信令/密钥 | SEC-2x 设备凭据与服务端身份 |
| T3 | 恶意客户端冒充他人设备（伪造 MAC/克隆） | SEC-2x 设备身份；风险 R2 |
| T4 | 未授权者凭截获的远程码建立映射 | 授权判定链 L2（[05 §4](05-账号分组与授权模型.md)，决策 D7） |
| T5 | 越权访问对端内网 | 开放内网段白名单（决策 D15，FR-C-701） |
| T6 | 服务端 Web/客户端 Web 被局域网或公网扫描 | 仅本机监听（决策 D11） |
| T7 | 本机其他进程操作客户端本地 Web | 仅 127.0.0.1 监听；管理面 HTTP 的已知残余风险见 R1 |
| T8 | STUN/中继被第三方滥用 | FR-S-603 认证开放；中继仅受理已授权会话 |
| T9 | 撞库与在线爆破（公网控制端口 / 管理 Web 的口令尝试）（v0.13） | SEC-63 登录防爆破；SEC-71/73 告警与封禁 |
| T10 | 开放设备注册被滥用（陌生设备入默认分组获得组内互访）（v0.13） | SEC-61/62 注册准入闸门与入组策略 |

## 2. 数据面加密能力（SEC-1x）

| 编号 | 能力要求 | 优先级 |
|---|---|---|
| SEC-11 | 节点间业务流量端到端加密：密钥仅通信双方持有；**中继路径下服务端仍不可解密** | P0 |
| SEC-12 | 加密具备机密性、完整性、防重放能力 | P0 |
| SEC-13 | 密钥由通信双方协商生成，经服务端控制面协助交换（交换过程本身须防中间人，见 SEC-21） | P0 |
| SEC-14 | 密钥可轮换：支持周期性轮换与手动触发；轮换不中断存量映射 | P1 |
| SEC-15 | 算法与封装方案可插拔，预留抗 DPI 混淆扩展位（首版不实现，决策 D5） | P2 |

> 参考：WireGuard 的密码学组件（Noise/X25519/ChaCha20-Poly1305）满足以上全部能力，是候选实现之一；最终选型在技术设计阶段确定。

## 3. 身份与凭据（SEC-2x）

| 编号 | 能力要求 | 优先级 |
|---|---|---|
| SEC-21 | 设备身份三段式：MAC 初始识别码（仅首次）→ 服务端签发设备 ID（权威、本地持久化）→ 远程码（别名）。身份校验以设备 ID 为准（决策 D6） | P0 |
| SEC-22 | 设备与服务端之间的控制通道通信须能防重放与防冒用（注册/信令/配置同步） | P0 |
| SEC-23 | 设备 ID 凭据存储于本机时须限制访问权限（文件权限/DPAPI 等平台机制，实现阶段选型） | P1 |
| SEC-24 | 用户密码不得明文存储（加盐哈希，算法实现阶段选型） | P0 |
| SEC-25 | 远程码可重置且即时失效（FR-S-903），防止长期泄露累积风险 | P1 |
| SEC-26 | 登录族消息（0x20/0x21/0x23）的密码字段在控制信道上**加密传输**（ECIES，沿 OQ-15 deviceSecret 下发模式；密钥分发与封装格式技术设计定），链路嗅探不可得明文（v0.13/M5，安全评估 P0#1；D21 维持——其余字段明文属 R1 知情接受范围） | P0 |

## 4. 管理面安全（决策 D11 的落地与残余风险）

| 面 | 约定 |
|---|---|
| 客户端本地 Web | **仅监听 127.0.0.1**，局域网/虚拟 IP 均不可达；HTTP |
| 服务端 Web | **仅监听本机地址**，不对公网暴露；HTTP；远程管理走"服务端机器部署客户端 + 端口映射"（流程 F7），流量在加密隧道内 |
| 首启向导 | 服务端地址配置页仅在未注册状态可访问核心操作；注册完成后向导锁定 |

> **残余风险 R1（已知情接受）**：管理页使用 HTTP 明文。客户端侧风险限于本机进程嗅探（127.0.0.1）；服务端侧流量在隧道内加密传输，明文仅存在于服务端本机回环。决议 OQ-9：现阶段不引入 TLS，保留为长期加固可选项。
>
> **M5 注记（v0.13）**：SEC-26 落地后登录族密码字段不再明文，控制信道明文暴露面收敛为端点/元信息类；D11/D21 口径不变。

## 5. 授权与暴露面（摘要，详见 [05](05-账号分组与授权模型.md)）

| 编号 | 要求 | 优先级 |
|---|---|---|
| SEC-51 | 哑节点的一切业务数据拉取请求被服务端拒绝并可审计日志记录 | P0 |
| SEC-52 | 映射授权在服务端强制执行（非仅客户端自查） | P0 |
| SEC-53 | 对端内网访问默认拒绝，仅白名单网段放行，白名单变更即时生效 | P1 |

## 6. 准入与防滥用（SEC-6x，v0.13/M5 新增）

> 立项背景：2026-10-21 全量安全评估回流——开放设备注册（0x10 无开关/频控/总量约束，且注册路径硬编码直入默认分组）与 0x21 登录零防爆破为 P0；决议 OQ-20。

| 编号 | 能力要求 | 优先级 |
|---|---|---|
| SEC-61 | 设备注册准入三重闸门：`device_registration_open` 开关（**默认开放**，OQ-20；管理页可关、即时生效）＋单 IP 注册频率限制（令牌桶）＋设备总数上限（`max_devices` 实施生效）——任一不满足即拒绝并可审计 | P0 |
| SEC-62 | 新设备注册入组须遵循默认分组准入策略：策略为 approval 时进入待审队列而非自动入组可见（修复现状=注册路径硬编码 `Approved=true` 直入，策略仅约束 0x51 凭码入组） | P0 |
| SEC-63 | 登录防爆破（双载体）：控制信道 0x21 按账户＋来源 IP 双维失败限流（递增延迟/封顶）；管理端 Web change-password 与 login 同款失败延迟（消除第二爆破入口）；限流触发与解除可审计 | P0 |
| SEC-64 | 监听面资源上限：控制端口单 IP 并发连接与总连接上限、中继 UDP JOIN 到达速率限制、管理 Web 连接数上限——防认证前资源耗尽 | P1 |

## 7. 安全监测与响应（SEC-7x，v0.13/M5 新增）

> 立项定位（用户目标）：预警后**人工介入**保障服务安全——审计与处置动作已齐（M2~M3 交付），本组补齐中间缺失的"聚合→阈值→推送"层与快速闸门。

| 编号 | 能力要求 | 优先级 |
|---|---|---|
| SEC-71 | 安全事件告警通道：可配置 webhook（管理页配置＋测试推送）；阈值触发先行三类——登录族失败聚合（0x21/0x23/admin 登录/admin 改密四入口，SEC-63 共享计数的自然超集——v0.15/OQ-22③ 措辞修正，原「0x21 与 admin 双源」字面过窄）、新设备注册（register/register_recover）、STUN 认证丢弃速率 | P1 |
| SEC-72 | 管理端安全中心：安全事件聚合视图（失败登录/新注册/授权拒绝等计数）＋一键处置入口（封/解 IP、注册开关快切、踢会话） | P1 |
| SEC-73 | IP 黑名单：手动加黑/解封＋可配置自动封禁（时间窗内失败次数阈值→封禁时长）；对控制/STUN/中继/管理 Web 四个监听面生效；命中可审计（v0.15/OQ-22① 口径细化：命中以 per-面计数器可观测、处置动作 ip_block/ip_unblock/ip_auto_block 入审计——不逐条写命中审计行，防审计自淹） | P1 |

## 8. 平台加固（SEC-8x，v0.13/M5 新增）

| 编号 | 能力要求 | 优先级 |
|---|---|---|
| SEC-81 | 服务端最小权限运行：专用非特权账户＋systemd 沙箱指令（NoNewPrivileges/ProtectSystem/ReadWritePaths 等；3478 低端口以 AmbientCapabilities 授权）；部署手册与 Docker 镜像 USER 随更 | P1 |
| SEC-82 | 客户端本地 Web 请求鉴权：服务启动生成随机 token（ACL 受控文件落盘），本地 API/WS 请求须携带、未携带即拒绝——收敛本机任意进程驱使 SYSTEM 服务的代理面；仍仅监听 127.0.0.1（D11） | P1 |
| SEC-83 | 静态数据加密：服务端 DB 中 deviceSecret 等凭据字段以主密钥加密存储（密钥来自配置/环境、不落库；v0.15/OQ-22② 缺钥降级口径：缺失不阻断启动、加密不启用＋ERROR 告警与管理页横幅——存量部署升级不断服，库文件权限仍为首道防线，补配后启动迁移自动完成；不可解密文行=该行凭据失效走解绑重注册）；库文件权限收紧 | P2 |
| SEC-84 | 升级链路完整性：update_url 强制 https；升级页展示产物哈希；发布产物签名（实施形态技术设计定，不可行则降级哈希核验+手册指引） | P2 |
| SEC-85 | 控制信道输入长度上限：用户名（0x20）/分组名（0x50·0x55）/设备名（0x10 Hostname）服务端统一 trim 后 1~64 校验（与客户端本地 API 同口径） | P2 |

## 9. 风险清单

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | 管理面 HTTP 明文（决策 D11） | 中 | 仅回环/隧道内承载；决议 OQ-9：现阶段不引入 TLS，保留为长期加固可选项；M5 后登录密码字段经 SEC-26 加密（明文面收敛为元信息） |
| R2 | MAC 重复/伪造（虚拟机克隆） | 中 | 服务端签发设备 ID 为准；管理员解绑重注册（FR-S-103）；克隆机器因设备 ID 不同需重新走授权 |
| R3 | TCP 端口预测命中率依赖 NAT 行为（顺序分配假设） | 中 | 并发路数可配置（1~5，默认 3→+2，OQ-1 决议）供不同 NAT 行为调优；失败回退中继 |
| R4 | 企业/运营商环境封锁 UDP | 中 | TCP 打洞与 TCP 中继承载（OQ-4）；混淆扩展位（SEC-15） |
| R5 | 误用 .NET 8/9（2026-11-10 停止支持） | 高 | 目标框架锁定 .NET 10（决策 D13，[08 §4](08-非功能需求.md)） |
| R6 | 默认管理员 admin/admin 被遗忘修改或凭据丢失 | 中 | 初始账号 **admin/admin**（决议 OQ-3），首次登录提示修改；密码丢失时的恢复手段在技术设计阶段定义 |
