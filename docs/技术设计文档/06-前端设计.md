- 包管理 pnpm workspace；Node ≥ 20 LTS。

### 1.1 共享样式层与视觉规范（v1.60，2026-10-20 评估批次 B）

`ui-shared/src/styles/shared.css` 经包子路径导出 `@p2p/ui-shared/styles.css`，两端 main.ts 引入，收敛原各页 scoped 复制漂移（评估 V-3：.toolbar×5/.muted×7/.error×3/.dot×4/码胶囊×2）。约定：

- 工具类：`.toolbar`（页头标题+操作行）、`.muted`（弱化文字，字号定档 12px）、`.error`（表单内联错误——错误呈现统一策略：表单提交内联、行内/批量操作 toast）、`.dot`（状态点）、`.code-pill`（远程码/网段等值胶囊）；页面不再自定义同名 scoped 类；
- 状态点语义色：`.dot` 默认=离线灰（正常态，--el-text-color-disabled）、`.dot.on`=在线绿、`.dot.danger`=异常红（仅控制通道断开等告警语义——评估定案"离线不是错误"）；
- 主色沿用 Element Plus 出厂蓝 `#409eff`（批复口径），色值一律引用 `--el-*` 变量不自造；favicon=两端 public/favicon.svg（EP 蓝圆角方块+两节点连线）；
- 表单 label-width 定档三刻度 72/88/140；
- 深色模式与窄屏响应式为评估暂缓项，未实施。

v1.60 落地注记（2026-10-20 评估批次 A+B+C，全量实施见问题清单台账处置记录）：①状态词全站统一**"直连"**（原直达/直连/direct 三叫法并存——StatusTag、server-app 两处 STATUS_LABELS、client Mappings 路径列均中文化）；②client `/login` 未登录态改**全屏居中**（App.vue 增 bare 模式免布局渲染，沿 server-app 先例；已登录账号管理仍嵌布局），菜单入口"账号"→"账号登录"；③交互防护补齐：登出二次确认+loading、停用映射二次确认、改密错误内联化、隧道 PING maxlength 8→6、向导按钮"注册并完成"；④技术码收敛：失败详情 tooltip 经 8 枚中文映射（punch_timeout→打洞超时等，附注保留原文），文案内嵌码（3002/4002/4003/0x75/02 §2.5/FR-C-603/1003）转白话——诊断区保留技术词；⑤图标体系：@element-plus/icons-vue 入两端（开发规范 01 白名单已录），AdminLayout 菜单项 `icon?: Component` 渲染 el-icon，client 9 项/server 7 项配图标；⑥echarts 死依赖移除（声明未用，图表实为手写 SVG）。状态点补 role="img"+aria-label（评估 U-9）。

**简易版科技感皮肤（v1.62，2026-10-20 用户指令"简易版要有科技感"）**：简易版专属深色霓虹视觉（FR-C-810"时尚性"的实现层），与高级版浅色出厂态并存——SimpleLayout 挂载期给 `<html>` 加 `dark`+`simple-tech` 双类、卸载期（含路由切走）摘除，高级版/登录页/向导页不受影响；**全站深色模式仍为评估暂缓项，本皮肤不是其实现**。实现分工：

- `main.ts` 引 `element-plus/theme-chalk/dark/css-vars.css`（EP 官方暗色变量，仅 `html.dark` 生效——全局兜底所有 EP 组件含 teleport 弹层/下拉/MessageBox）；

## 4. 状态与实时（TD-16：REST 是真相、WS 只是提示）

WS 事件可能丢失/乱序/陈旧（断连间隙、多事件竞达），因此**一切状态以 REST 响应为准**，WS 仅充当"该去刷新了"的提示信号：

```
Pinia stores:
  useSystemStore   # /api/system/state + /api/device 轮询 10s
  useAuthStore     # 登录态、能力模式（login_state 事件触发 refetch）
  useMappingStore  # 列表与状态经 REST；速率行内更新（mapping_stats）
  useDeviceStore   # device_list 事件触发 refetch（0x40 分页 hasMore 循环拉全量，OQ-16）
```

**事件分级处理**：

| 级别 | 事件 | 处理 |
|---|---|---|
| 高频数值类 | mapping_stats（1s 速率） | 直接写入 store——下秒覆盖，丢失/陈旧无害 |
| 状态类 | mapping_state / device_list / login_state | **不直接改 store**，仅触发对应资源 refetch（100ms debounce 合并突发） |

M2-28 注记：状态类事件在 refetch 之外经 useWs `onState` 旁路透传原始事件对象（仅提示用途，不改 store）——`mapping_state invalid` → 全局失效提示（0x75 链，列表置灰仍由 refetch 完成）；设备列表 10s 轮询已移除，由 device_list 事件 + onOpen/visibilitychange resync 兜底。

**resync 时机**（丢失事件的兜底）：

- WS `onOpen`（含断线重连成功）→ 全量 refetch（system / mappings / devices）；
- 页面 `visibilitychange → visible`（睡眠唤醒/切回标签页）→ 全量 refetch。

useWs：指数退避重连（1s 起，上限 30s）；本地回环全量拉取毫秒级完成，故**明确否决** seq+增量补发方案（复杂度不匹配收益）。网络断连时页面显示"服务不可达"全局条（本地服务进程存活检测）。
